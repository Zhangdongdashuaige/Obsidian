# JVM内存结构
---
![[JVM-1.png]]
Java虚拟机定义了若干程序运行期间回使用到的运行时数据区，其中有一些会随着虚拟机启动而创建，随着虚拟机退出而销毁。另外一些则是与线程一一对应的，这些线程一一对应的数据区域会随着县城开始和结束而创建和销毁。
- **线程私有：程序计数器、虚拟机栈、本地方法区
- **线程共享：堆、方法区、堆外内存（java7的永久代或java8的元空间、代码缓存）**
栈是运行时的单位，堆是存储的单位
## 一、程序计数器（program Counter Register）

==***JVM中的PC寄存器是对物理PC寄存器的一种抽象模拟***==，并非是广义上所指的物理寄存器。

pc寄存器用来存储指向下一条指令的地址，即将要执行的指令代码。由执行引擎读取下一条指令。（此处指令指的是字节码文件反解析后的操作指令）

## 二、Java虚拟机栈（Java栈）

<span style="background-color:yellow"><b>Java虚拟机栈是描述Java方法运行过程的内存模型。</b></span>

- 栈是一种给快速有效的分配存储方式，访问速度仅次于程序计数器
- JVM直接堆虚拟机栈的操作只有两个：每个方法执行，伴随着入栈（进栈/压栈），方法执行结束出栈
- <span style="background-color:yellow"><b>栈不存在垃圾回收问题</b></span>

**栈中可能出现的异常：**
==**Java虚拟机规范允许Java虚拟机栈的大小是动态的或者是固定不变的**==
- 如果采用固定大小的Java虚拟机栈，那每个线程的Java虚拟机栈容量可以在线程创建时独立选定。如果线程请求分配的栈容量超过Java虚拟机栈允许的最大容量，Java虚拟机将会抛出一个StackOverError异常
- 如果Java虚拟机栈可以动态扩展，并且在尝试扩展时无法申请到足够的内存，或者在创建新的线程时没有足够的内存去创建对应的虚拟机栈，那Java虚拟机将会抛出一个OutOfMemoryError异常
可以通过参数`-Xss`来设置线程的最大栈空间，栈的大小直接决定了函数调用的最大可达深度
官方提供的参数设置参考：<a href="https://docs.oracle.com/javase/8/docs/technotes/tools/windows/java.html#BGBCIEFC">参考文档</a> 
### 2.1 栈的存储单位

- 每个线程都有自己的栈，栈中的数据都是以**栈帧**（Stack Frame）的格式存在。
- 在这个线程上正在执行的每个方法都各自有对应的一个栈帧。
- 栈帧是一个内存区块，是一个数据集，维系着方法执行过程中的各种数据信息。

### 2.2 栈帧的内部结构

**Java虚拟机栈会为每一个即将运行的Java方法创建一块名为栈帧的区域，用于存放该方法运行过程中的一些信息**，如：
- <font color = 'red'>局部变量表（Local Variables)</font>
- <font color = 'red'>操作数栈 (Operand Stack) (或表达式栈)</font>
- 动态链接 (Dynamic Linking) (或指向运行时常量池的方法引用)
- 方法返回地址 (Return Address) (或方法正常退出或异常退出的定义)
- ......
![[img/JVM.png]]
当方法运行过程中需要创建局部变量时，就将局部变量的值存入栈帧中的局部变量表中。
栈帧是一个内存区域，是一个数据集，维系着方法执行过程中的各种数据信息
- 在一条活动线程中，一个时间点上只会有一个活动的栈帧。即只有当前正在执行的方法的栈帧（栈顶栈帧）是有效的，这个栈帧被称为栈顶栈帧，与当前栈帧对用的方法就是当前方法，定义这个方法的类就是当前类。
- 执行引擎运行的所有字节码指令只针对当前栈帧进行操作
- 如果在该方法中调用了其他方法，对应的新的栈帧会被创建出来，放在栈的顶端成为新的栈帧

**局部变量表：**
- 局部变量表也被称之为局部变量数组或本地变量表
- 是一组变量值存储空间，主要用于存储方法参数和定义在方法体内的局部变量，包括编译器可知的各种Java虚拟机==`基本数据类型`==（byte、int、short、long、char、float、double、boolean）、==`对象引用`==（reference类型，并不等同于对象本身，可能是一个指向对象起始地址的引用指针，也可能是指向一个代表对象的句柄或其他与此相关的位置）和==returnAddress==类型（指向了一条字节码指令的地址，已被异常表取代）
- 局部变量表是建立在线程的栈上，是线程的私有数据，因此==`不存在数据安全问题`==
- <span style="background-color:yellow"><b>局部变量表所需要的容量大小是编译期确定下来的</b></span>，并保存在方法的Code属性的==`maximum local variables`==数据项中。在方法运行期间是不会改变局部变量表的大小的
- 方法嵌套调用的次数由栈的大小决定。==`一般来说，栈越大，方法嵌套调用的次数越多。`==对一个函数而言，他的参数和局部变量越多，他所占用的栈帧的大小就越大，导致其嵌套的调用次数就会减少
- ==`局部变量表的变量只会在当前方法调用中有效`==。在方法执行时，虚拟机通过使用局部变量表完成参数值到参数变量列表的传递过程。
- 参数值的存放总是在局部变量数组的index0开始，到数组长度-1的索引结束
局部变量表的基本存储单位是==**槽Slot**==
1. 在局部变量表中，32位以内的类型只占用一个Slot（包括return Address类型），64位的类型（long和double）占用两个连续的Slot
    1. byte、short、char在存储前被转换位int，boolean也被转换为int
    2. long和double占据两个slot
 2. JVM会为局部变量表中的每一个slot都分配一个访问索引，通过这个索引即可访问局部变量表中的指定局部变量值
 3. 当一个实例方法被调用的时候，他的方法参数和方法体内部定义的局部变量将会按照顺序被复制到局部变量表中的每一个slot上
 4. 如果需要访问局部变量表中一个64bit的局部变量是，只需要使用其前一个索引即可
 5. 如果当前帧是由构造方法或实例方法创建的，那么该对象的引用this将会存放在index为0的Slot处（**为什么静态方法中不可以引用this？因为this变量不存在于当前方法的局部变量表中**）
 6. 局部变量表中的槽位是可以重复使用的，当一个局部变量过了其作用域，那么该变量所使用的槽位就可以释放出来供其他局部变量使用
![[slot复用.png]]
7. 在栈帧中，与性能调优关系最为密切的就是局部变量表。在方法执行时，虚拟机使用局部变量表完成方法的传递
8. ==局部变量表中的变量也是重要的垃圾回收根节点，需要被局部变量表中直接或间接引用的对象都不会被回收==
