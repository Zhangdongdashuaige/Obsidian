# Java类加载机制
---
## 一、类的生命周期
类的加载过程包括了`加载`、`验证`、`准备`、`解析`、`初始化`五个阶段。在这五个阶段中，`加载`、`验证`、`准备`和`初始化`这四个阶段发生的顺序是确定的，而`解析`阶段则不一定，它在某些情况下可以在初始化阶段之后开始，这是为了支持Java语言的运行时绑定（也称为动态绑定或晚期绑定）。另外这里的几个阶段是按顺序开始，而不是按顺序进行或完成，因为这些阶段通常都是互相交叉地混合进行的，通常在一个阶段执行地过程中调用或激活另一个阶段。
![[类加载流程图.png]]
### 类的加载：查找并加载类的二进制数据
加载时类加载过程中的第一个阶段，在加载阶段，虚拟机需要完成以下三件事情：
- 通过一个类的全限定名来获取其定义的二进制字节流
- 将这个字节流所代表的静态存储结构转化为方法区的运行时数据结构
- 在Java堆中生成一个代表这个类的java.lang.Class对象，作为对方法区中这些数据的访问入口
![[加载过程.png]]
相对于类加载的其他阶段而言，_加载阶段(准确地说，是加载阶段获取类的二进制字节流的动作)是可控性最强的阶段_，因为开发人员既可以使用系统提供的类加载器来完成加载，也可以自定义自己的类加载器来完成加载。

加载阶段完成后，虚拟机外部的 二进制字节流就按照虚拟机所需的格式存储在方法区之中，而且在Java堆中也创建一个`java.lang.Class`类的对象，这样便可以通过该对象访问方法区中的这些数据。

类加载器并不需要等到某个类被“首次主动使用”时再加载它，JVM规范允许类加载器在预料某个类将要被使用时就预先加载它，如果在预先加载的过程中遇到了.class文件缺失或存在错误，类加载器必须在程序首次主动使用该类时才报告错误(LinkageError错误)如果这个类一直没有被程序主动使用，那么类加载器就不会报告错误。

**加载.class文件的方式**
- 从本地系统中直接加载
- 通过网络下载.class文件
- 从zip，jar等归档文件中加载.class文件
- 从专有数据库中提取.class文件
- 将Java源文件动态编译为.class文件

# JVM内存结构
---
![[JVM-1.png]]
Java虚拟机定义了若干程序运行期间回使用到的运行时数据区，其中有一些会随着虚拟机启动而创建，随着虚拟机退出而销毁。另外一些则是与线程一一对应的，这些线程一一对应的数据区域会随着县城开始和结束而创建和销毁。
- **线程私有：程序计数器、虚拟机栈、本地方法区
- **线程共享：堆、方法区、堆外内存（java7的永久代或java8的元空间、代码缓存）**
栈是运行时的单位，堆是存储的单位
## 一、程序计数器（program Counter Register）
<span class="yellow-bold">VM中的PC寄存器是对物理PC寄存器的一种抽象模拟</span>，并非是广义上所指的物理寄存器。

pc寄存器用来存储指向下一条指令的地址，即将要执行的指令代码。由执行引擎读取下一条指令。（此处指令指的是字节码文件反解析后的操作指令）
![[JVM-2.png]]

## 二、Java虚拟机栈（Java栈）
<span style="background-color:yellow"><b>Java虚拟机栈是描述Java方法运行过程的内存模型。</b></span>

- 栈是一种给快速有效的分配存储方式，访问速度仅次于程序计数器
- JVM直接堆虚拟机栈的操作只有两个：每个方法执行，伴随着入栈（进栈/压栈），方法执行结束出栈
- <span class="yellow-bold">栈不存在垃圾回收问题</span>

**栈中可能出现的异常：**
<span class="yellow-bold">Java虚拟机规范允许Java虚拟机栈的大小是动态的或者是固定不变的</span>
- 如果采用固定大小的Java虚拟机栈，那每个线程的Java虚拟机栈容量可以在线程创建时独立选定。如果线程请求分配的栈容量超过Java虚拟机栈允许的最大容量，Java虚拟机将会抛出一个StackOverError异常
- 如果Java虚拟机栈可以动态扩展，并且在尝试扩展时无法申请到足够的内存，或者在创建新的线程时没有足够的内存去创建对应的虚拟机栈，那Java虚拟机将会抛出一个OutOfMemoryError异常
可以通过参数`-Xss`来设置线程的最大栈空间，栈的大小直接决定了函数调用的最大可达深度
官方提供的参数设置参考：<a href="https://docs.oracle.com/javase/8/docs/technotes/tools/windows/java.html#BGBCIEFC">参考文档</a> 
### 2.1 栈的存储单位
- 每个线程都有自己的栈，栈中的数据都是以**栈帧**（Stack Frame）的格式存在。
- 在这个线程上正在执行的每个方法都各自有对应的一个栈帧。
- 栈帧是一个内存区块，是一个数据集，维系着方法执行过程中的各种数据信息。

### 2.2 栈帧的内部结构 
**Java虚拟机栈会为每一个即将运行的Java方法创建一块名为栈帧的区域，用于存放该方法运行过程中的一些信息**，如：
- <font color = 'red'>局部变量表（Local Variables)</font>
- <font color = 'red'>操作数栈 (Operand Stack) (或表达式栈)</font>
- 动态链接 (Dynamic Linking) (或指向运行时常量池的方法引用)
- 方法返回地址 (Return Address) (或方法正常退出或异常退出的定义)
- ......
![[img/JVM.png]]
当方法运行过程中需要创建局部变量时，就将局部变量的值存入栈帧中的局部变量表中。
栈帧是一个内存区域，是一个数据集，维系着方法执行过程中的各种数据信息
- 在一条活动线程中，一个时间点上只会有一个活动的栈帧。即只有当前正在执行的方法的栈帧（栈顶栈帧）是有效的，这个栈帧被称为栈顶栈帧，与当前栈帧对用的方法就是当前方法，定义这个方法的类就是当前类。
- 执行引擎运行的所有字节码指令只针对当前栈帧进行操作
- 如果在该方法中调用了其他方法，对应的新的栈帧会被创建出来，放在栈的顶端成为新的栈帧

**局部变量表：**
- 局部变量表也被称之为局部变量数组或本地变量表
- 是一组变量值存储空间，主要用于存储方法参数和定义在方法体内的局部变量，包括编译器可知的各种Java虚拟机<span class="yellow-bold">基本数据类型</span>（byte、int、short、long、char、float、double、boolean）、<span class="yellow-bold">对象引用</span>（reference类型，并不等同于对象本身，可能是一个指向对象起始地址的引用指针，也可能是指向一个代表对象的句柄或其他与此相关的位置）和<span class="yellow-bold">returnAddress</span>类型（指向了一条字节码指令的地址，已被异常表取代）
- 局部变量表是建立在线程的栈上，是线程的私有数据，因此<span class="yellow-bold">不存在数据安全问题</span>
- <span class="yellow-bold">局部变量表所需要的容量大小是编译期确定下来的</span>，并保存在方法的Code属性的<span class="yellow-bold">maximum local variables</span>数据项中。在方法运行期间是不会改变局部变量表的大小的
- 方法嵌套调用的次数由栈的大小决定。<span class="yellow-bold">一般来说，栈越大，方法嵌套调用的次数越多。</span>对一个函数而言，他的参数和局部变量越多，他所占用的栈帧的大小就越大，导致其嵌套的调用次数就会减少
- <span class="yellow-bold">局部变量表的变量只会在当前方法调用中有效</span>。在方法执行时，虚拟机通过使用局部变量表完成参数值到参数变量列表的传递过程。
- 参数值的存放总是在局部变量数组的index0开始，到数组长度-1的索引结束

局部变量表的基本存储单位是<span class="yellow-bold">槽Slot</span>
1. 在局部变量表中，32位以内的类型只占用一个Slot（包括return Address类型），64位的类型（long和double）占用两个连续的Slot
    1. byte、short、char在存储前被转换位int，boolean也被转换为int
    2. long和double占据两个slot
 2. JVM会为局部变量表中的每一个slot都分配一个访问索引，通过这个索引即可访问局部变量表中的指定局部变量值
 3. 当一个实例方法被调用的时候，他的方法参数和方法体内部定义的局部变量将会按照顺序被复制到局部变量表中的每一个slot上
 4. 如果需要访问局部变量表中一个64bit的局部变量是，只需要使用其前一个索引即可
 5. 如果当前帧是由构造方法或实例方法创建的，那么该对象的引用this将会存放在index为0的Slot处（**为什么静态方法中不可以引用this？因为this变量不存在于当前方法的局部变量表中**）
 6. 局部变量表中的槽位是可以重复使用的，当一个局部变量过了其作用域，那么该变量所使用的槽位就可以释放出来供其他局部变量使用
![[slot复用.png]]
7. 在栈帧中，与性能调优关系最为密切的就是局部变量表。在方法执行时，虚拟机使用局部变量表完成方法的传递
8. <span class="yellow-bold">局部变量表中的变量也是重要的垃圾回收根节点，需要被局部变量表中直接或间接引用的对象都不会被回收</span>

**操作数栈（Operand Stack）**
在方法执行过程中，根据字节码指令，往栈中写入数据或提取数据
